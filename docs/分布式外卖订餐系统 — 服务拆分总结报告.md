## 四、核心设计决策

### 4.1 错误码体系（int方案）

**采用"折中方案"：**

- `code` 字段类型为 `Integer`（不是 `String`）
- `R` 响应中新增 `source` 字段标识来源服务- 错误码按业务域分段（1xxx 公共、2xxx 用户、3xxx 商品、4xxx 订单、8xxx 管理、9xxx 系统）

| 段位      | 用途        | 归属        |
| --------- | ----------- | ----------- |
| 1001-1099 | 通用/参数   | del-common  |
| 2001-2099 | 用户/认证   | del-user    |
| 3001-3099 | 商品/库存   | del-product |
| 4001-4099 | 购物车/订单 | del-order   |
| 8001-8099 | 管理员      | del-admin   |
| 9001-9099 | 系统        | del-common  |

### 4.2 JWT 密钥分层设计

| 服务类别             | JWT密钥            | Redis key 前缀     | 用途                                                         |
| -------------------- | ------------------ | ------------------ | ------------------------------------------------------------ |
| **C 端服务（共用）** | `del-user-secret`  | `del-user:auth:*`  | del-user / del-product / del-order / del-comment 共享 token 池 |
| **B 端服务（独立）** | `del-admin-secret` | `del-admin:auth:*` | del-admin 独立 token池                                       |

**关键点：**

- C 端 token 在4 个服务间通用（用户登录一次访问所有 C端服务）
- B 端 token 完全隔离（管理员 token 无法用于 C 端接口）
- 防止 C/B 端横向越权

### 4.3 异常处理统一化

- **单一异常类**：`BizException`（移除 `BusinessException`）
- **支持占位符**：`new BizException(ProductErrorCode.NOT_FOUND, 123)` → `"商品[123]不存在"`
- **全局处理器位于 `del-common`**：`@RestControllerAdvice` 自动注册到所有服务
- **`source` 自动注入**：`GlobalExceptionHandler.determineSource()` 从请求 URI 提取服务名

### 4.4 实体基类与通用字段

`BaseEntity`字段：

- `id`（`@TableId(type = IdType.AUTO)` 自增主键）
- `createTime`（`@TableField(fill = FieldFill.INSERT)` 自动填充）
- `updateTime`（`@TableField(fill = FieldFill.INSERT_UPDATE)` 自动填充）
- `isDeleted`（`@TableLogic` 逻辑删除标记）

`MybatisPlusConfig` 实现 `MetaObjectHandler` 完成时间戳自动填充。

### 4.5 Snowflake 下沉（消除反模式）

**原方案（反模式）：**独立微服务 + Feign 调用
-性能：5-50ms（远程调用）

- 单点故障：服务挂了所有写库阻塞

**新方案：**

- Snowflake 算法下沉到 `del-common/utils/SnowflakeIdGenerator.java`
- 各服务本地调用：`@Import(SnowflakeAutoConfiguration.class)`
- 性能：10ns（本地调用）
- 无单点故障

### 4.6 依赖收敛原则

`del-common` 的依赖收敛到**最少必要**：

- ✅ Spring Boot Web（`GlobalExceptionHandler` 需要）
- ✅ Spring Security（认证异常类）
- ✅ Spring Validation（`@Valid`）
- ✅ JWT（jjwt）
- ✅ OpenFeign（`IdGeneratorApi` 需要）
- ✅ MyBatis Plus（**provided**，BaseEntity 注解需要，不传递）
- ✅ Hutool（`BizException` 占位符）
- ✅ Lombok（**provided**）
- ❌移除业务层框架（防止污染依赖）

## 五、关键技术亮点

### 5.1 库存 CAS 乐观锁（del-product）

```
-- ProductMapper原子扣减
UPDATE t_product SET stock = stock - #{quantity}
WHERE id = #{productId} AND stock >= #{quantity} AND is_deleted = 0

-- CAS 模式（修改库存到指定值）
UPDATE t_product SET stock = #{newStock}
WHERE id = #{productId} AND stock = #{expectedStock} AND is_deleted = 0
```

并发场景下安全扣减，避免超卖。

### 5.2 Token 黑名单（双层防护）

- **单条 jti 黑名单**：登出时写入 Redis，TTL = token 剩余有效期
- **用户 jti 索引（SET）**：记录用户所有活跃 token jti，用于一键踢下线（冻结用户）

Redis key：`del-user:auth:blacklist:{jti}`、`del-user:auth:user:{userId}:jti`

### 5.3 订单地址快照

订单创建时将收货人姓名、电话、地址完整记录到订单主表（不只存 addressId）。即便后续用户修改地址，原订单的收货信息不受影响。

### 5.4 商品快照`OrderItem` 中冗余存储 `productName`、`productCover`、`productPrice`。即便商品被修改或删除，原订单的商品信息不受影响。

### 5.5 B 端双层权限校验

`SecurityConfig`：
-路径级：`requestMatchers("/api/v1/admin/**").hasAnyRole("ADMIN","SUPER_ADMIN")`

- 方法级：`@PreAuthorize("hasRole('SUPER_ADMIN')")`（如需更细粒度）
